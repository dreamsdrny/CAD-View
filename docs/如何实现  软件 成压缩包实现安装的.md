# 如何实现软件打成压缩包、解压安装并双击运行

## 1. 当前推荐的使用方式

本项目是 **C++20 + Qt 6 Widgets** 桌面程序，最终运行文件是 `CAD.exe`。

### 自己开发和调试

在 `D:\Evan\CAD-Software` 中：

1. 修改 C++ 源代码。
2. 关闭正在运行的开发版 CAD，双击 **`build.bat`**，完成编译、测试和运行库部署。
3. 双击 **`start.bat`** 启动最新版本。

也可以直接双击：

```text
D:\Evan\CAD-Software\build\native\bin\CAD.exe
```

`start.bat` 启动的是上述构建目录中的 EXE，不需要先安装。它不会自动重新编译；代码修改后必须先构建。需要断点调试时，用 Qt Creator 等 IDE 打开 `CMakeLists.txt`，选择匹配的 Qt/MinGW 工具链和 Debug 构建。

### 发给其他电脑

只发一个文件时，双击 **`package-exe.bat`**，得到：

```text
dist\CAD-0.2.1.exe
```

接收者直接双击这个 EXE 即可，不需要安装。它实际是 NSIS 自解压启动器：首次运行把程序释放到 `%LOCALAPPDATA%\Qiao\CAD-Portable\0.2.1`，随后启动 `CAD.exe`。它不创建快捷方式，不写卸载注册项；以后再次双击会复用已释放的文件。删除该缓存目录即可清理。

需要完整目录时，双击 **`package-portable.bat`**，得到：

```text
dist\CAD-0.2.1-Windows-x64.zip
```

接收者对 ZIP 执行“全部解压”，然后双击解压目录中的 `CAD\CAD.exe` 即可。这就是本项目的**免安装/便携版**。版本号从 CMake 构建缓存读取，将随项目版本更新。

单文件 EXE 与 ZIP 内容相同。ZIP 更适合排错和长期保存；单文件 EXE 更适合只复制一个文件给现场人员。

## 2. 为什么不能只压缩一个 EXE

本项目使用动态链接的 Qt 和 MinGW 运行库。必须把 EXE、DLL、Qt 插件及文档一起分发。

典型压缩包内容如下，实际依赖以 `windeployqt` 部署结果为准：

```text
CAD/
├── CAD.exe
├── Qt6Core.dll
├── Qt6Gui.dll
├── Qt6Widgets.dll
├── Qt6Network.dll
├── libgcc_s_seh-1.dll
├── libstdc++-6.dll
├── libwinpthread-1.dll
├── D3Dcompiler_47.dll
├── platforms/
│   └── qwindows.dll
├── styles/
├── imageformats/
├── generic/
├── networkinformation/
├── tls/
└── docs/
```

接收者无需安装 Python、Qt SDK、CMake 或编译器。`platforms/qwindows.dll` 的相对目录必须保留；不要只把 `CAD.exe` 拖到桌面。如果需要桌面入口，给 EXE 创建快捷方式。

## 3. 项目如何自动打包

入口与实现：

| 文件 | 作用 |
| --- | --- |
| `build.bat` | 构建、运行测试、部署运行库 |
| `start.bat` | 启动构建目录的 CAD |
| `package-exe.bat` | 生成便携 ZIP 和单文件 `CAD-0.2.1.exe` |
| `package-portable.bat` | 只生成便携 ZIP，不要求 NSIS |
| `package.bat` | 生成 ZIP、单文件 EXE 和 Setup 安装程序 |
| `scripts/build-native.ps1` | CMake、CTest、windeployqt 构建流程 |
| `scripts/package-native.ps1` | 从构建产物收集交付文件，压缩和启动验证 |
| `resources/windows/installer.nsi` | 可选 NSIS 安装器定义 |

便携包的完整流程：

```text
C++ 源代码
  → CMake 配置与编译
  → CTest 核心与界面测试
  → cmake --install 收集交付文件到新的暂存目录
  → windeployqt 部署 Qt、MinGW DLL 和插件
  → Compress-Archive 压缩完整 CAD 文件夹
  → 运行暂存目录 CAD.exe --smoke-test 检查启动
```

暂存目录形如 `build/native/package-<随机标识>/CAD`。`cmake --install --prefix ...` 在这里表示“收集文件到指定目录”，不会给 Windows 注册安装软件，也不会创建桌面快捷方式。

### 生成单文件 EXE

在项目根目录的 PowerShell 中运行：

```powershell
.\package-exe.bat
```

等价脚本命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-native.ps1 -SingleExe
```

刚刚已经成功构建和测试时，可以省去重复编译：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-native.ps1 -SingleExe -SkipBuild
```

`-SkipBuild` 使用现有 EXE，因此要先确认它对应最新源码。单文件 EXE 由 `resources/windows/portable.nsi` 生成。

### 只生成 ZIP

```powershell
.\package-portable.bat
```

等价脚本命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-native.ps1 -PortableOnly
```

刚刚已经成功构建和测试时，可以省去重复编译：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-native.ps1 -PortableOnly -SkipBuild
```

### 验证压缩包和单文件 EXE 可以独立运行

使用一个已经存在的临时目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-package.ps1 -Archive .\dist\CAD-0.2.1-Windows-x64.zip -SingleExe .\dist\CAD-0.2.1.exe -TemporaryRoot "$env:TEMP"
```

脚本检查 ZIP 内容，解压到新建的随机目录，暂时清除 Qt SDK 的路径影响，然后实际运行解压出来的 `CAD.exe --smoke-test`。它还会启动单文件 EXE，等待其释放缓存，并验证释放出的程序能独立启动。这样能证明 DLL 随包完整部署，而非依赖开发机环境。

### 同时生成传统安装程序

```powershell
.\package.bat
```

这需要 NSIS 3，输出另外一个 `dist/CAD-0.2.1-Setup.exe`。Setup 使用相同的应用文件，额外完成复制文件、创建桌面/开始菜单快捷方式、登记卸载信息、生成卸载器。生成 Setup 本身不会安装软件。

开发调试使用 `start.bat`；需要分发免安装版时使用 ZIP 即可。

## 4. 接收者如何“解压安装”

1. 将 ZIP 保存到本地磁盘。
2. 右键 ZIP → **全部解压**，选择固定目录，例如 `D:\Tools\QiaoCAD`。
3. 打开完整解压出的 `CAD` 文件夹。
4. 双击 `CAD.exe`。
5. 使用“打开 DXF / DWG”选择图纸。

请先解压，不要在压缩软件预览窗口中直接运行 EXE。Windows 加载程序时需要找到旁边的 DLL 和插件。

这个便携版不会登记到 Windows“已安装的应用”。当前程序的界面设置仍由 Qt `QSettings` 保存在当前用户设置中；“免安装”指无需安装程序，并不表示所有设置都存放在 ZIP 目录里。

DXF 可直接使用。DWG 功能仍需单独配置 ODA File Converter，它不包含在当前 ZIP 内。

## 5. 更新、删除和常见问题

- **更新**：关闭 CAD，将新版 ZIP 解压到新的文件夹，启动新版 EXE；桌面快捷方式如指向旧目录，需要重新指定。
- **删除便携版**：关闭 CAD，删除解压出的程序目录及自己创建的快捷方式即可。自己的图纸建议放在独立目录。
- **提示缺少 Qt6Core.dll / libstdc++-6.dll**：检查是否完整解压，而非只复制 EXE。
- **提示无法加载 Qt platform plugin windows**：检查 `platforms/qwindows.dll` 是否存在且层级正确。
- **修改代码后行为没有变化**：先关闭 CAD，运行 `build.bat`，然后通过项目的 `start.bat` 启动。
- **编译时无法写入 CAD.exe**：开发版进程可能仍占用 EXE，关闭后重新编译。
